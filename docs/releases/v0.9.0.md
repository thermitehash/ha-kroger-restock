# v0.9.0 — Crash-safe cart pushes, clearer IMAP picker, already-in-cart

**Cart pushes are saved first (priority fix)**
- Each item is written to disk as `pushing` before the cart call to Kroger and becomes `in_cart` only after Kroger confirms. A restart or crash mid-push, or no answer from Kroger, now leaves the item as **"May already be in your Kroger cart - check and confirm"** (status `check_cart`) instead of an untracked item in your cart, and it's never pushed twice automatically
- Settle it from **Settings → Repairs** (Confirm in cart / Push again / Remove) or the new `check_cart_item` action

**Already in the cart**
- `scan_upc`, `add_item` and `resolve_item` accept `already_in_cart: true`: the item is recorded as in the cart with no cart call (use it for items added in the Kroger app or for an untracked push). A needs-review item added this way is recorded when resolved

**Order tracking setup**
- The IMAP picker shows "<name> — folder: … · search: …", so two connections to the same mailbox can be told apart
- Picking a connection that searches `UnSeen` or watches INBOX shows a warning first
- README: the tested Gmail setup (filter → `Kroger` label, never to Spam, not applied to old mail; separate IMAP connection with folder `Kroger` and search `FROM "e.krogermail.com"`; event text + headers; default 2048 max size is fine because the full message is fetched)

**Docs**
- HACS refreshes custom repos about every 48 h: use **⋮ → Update information** to see a new release sooner
- Verified live: store attributes, the checklane aisle rule, items and log level surviving an update
