# v0.8.0 — Store locations, ignored-scan feedback, short UPC-E

**Store locations**
- Kroger's aisle number isn't always an aisle (a checkout-lane item came back as "aisle 300", "CHECKLANE 15"). The description now decides: "AISLE 12" → Aisle 12; check lanes/registers → the description ("Checklane 15"), grouped under **Front of store** on printouts; other areas (seasonal, endcaps) → their own named group. Printouts: numbered aisles, then named areas, then Front of store, then Other

**Ignored scans are no longer silent**
- A QR or other non-product code returns `result: ignored` with a message ("Ignored a QR or non-product code - aim at the barcode and cover any QR code"), fires `kroger_restock_scanned` with `result: ignored`, and sends a notification when notification targets are set (at most once every 30 s)
- ESPHome scanners blink amber twice for ignored codes (AtomS3 RGB LED; GM65 build: both LEDs)

**Barcodes**
- 6- and 7-digit codes are treated as UPC-E missing the number system and/or check digit: expanded to UPC-A with a computed check digit, then normalized

**Docs**
- iPhone Shortcut: cover the QR code; exact Perform Action data `{"upc": "<QR/Barcodes variable>", "source": "shortcut"}` with the variable inside the quotes; set the Action before typing data (the HA app crashes otherwise)
- Verified live: product calls with the user token, iPhone 13-digit codes, `stockLevel`, cart add
- "Already in cart" option parked on the roadmap
