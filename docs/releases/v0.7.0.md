# v0.7.0 — Store address, order-email hardening, AtomS3 scanner + housing

**Important fix**
- v0.6.0 reloaded the integration every ~30 minutes (each token refresh triggered the options listener), which kept restarting the stock-check timer so scheduled stock checks never ran. Options now reload only when you change them

**Store**
- Store picker and the to-do list (`store_name`, `store_address`, `location_id` attributes) show the street address next to Kroger's store name. Existing entries look the address up once
- Changing the store in options takes effect without a reinstall: entry renamed, per-store aisle/price/stock data cleared and re-read, entity IDs unchanged

**Order emails** (based on a year of real Kroger email patterns)
- Handles the older "Order Confirmed" subject, Instacart delivery confirmations (inline order number, pickup vs delivery told apart by the body), literal HTML and `&zwnj;` in the ready email, table pipes, and struck-through fees (`$4.95 $0.00` = 0.00)
- Final receipt completes the most recent ready pickup (or placed delivery) order from the last 24 h, otherwise it's ignored. Works with several household members ordering
- New attributes: `window_start` / `window_end` (HA time zone), `fee`, `completed`
- `shorted_items` / `substitutions` are now absent unless an email contained them (unknown vs none). Automatic re-add of shorted items is disabled entirely
- Order picked up/delivered → notification "Mark the N in-cart items received?" with **All received**, **Some missing…** (type what didn't come; those items go back on the list and into the cart for next time) and **Open list**. Kroger's last-minute out-of-stock/replacement notices come by text, so this is where you record them. New `mark_cart_received` action with an optional `missing` list. Nothing is checked off automatically
- Only `email@e.krogermail.com` (and other Kroger-family order senders) is read; the developer-portal email is ignored. Dedupe by Message-ID/content as well as IMAP UID
- IMAP folder guidance for Gmail (Promotions tab, archived mail)

**Scanner**
- New recommended build: M5Stack AtomS3 Lite + Atomic QRCode2 Base (no soldering), configures the scan engine at boot, RGB LED feedback (green/amber/blue/red), button = print / long-press sync
- 3D-printable wall housing (parametric OpenSCAD + STLs) under `hardware/housing/`
- GM65 build kept as an alternative

**Setup and debugging**
- Setup starts with a note to complete the Kroger sign-in on a computer
- Debug logs show which token each product call used and every barcode candidate tried

Not affiliated with Kroger.
